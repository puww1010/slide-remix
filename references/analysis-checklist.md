# 模式 A：截图拆解清单

## 先找证据（必要时用 PIL 放大局部再看）
| 看什么 | 能说明什么 |
|---|---|
| 外框：灰底中间一张白卡片、底部有拖拽把手、右侧露出光标 | 是在某个应用的预览面板里截的图，不是 PowerPoint 编辑界面 |
| 左上角装饰线、底部版权条、logo | 用了哪家公司的哪套模版（对比已知模版的渲染图） |
| 连线交叉处的跳线弧 | PowerPoint 做不出来，说明是 SVG 手写或 draw.io |
| 线上标签带白底、标签被箭头从中间切开 | 程序自动摆放的痕迹，通常是 AI 生成的 SVG |
| 字体：Helvetica / system-ui，还是 Calibri / Aptos，还是模版字体（例：Figtree） | 网页渲染，还是 Office 默认，还是套了模版 |
| 对齐精度：同一排元素的高度是否一致，段间距是否统一 | 坐标完全整齐通常是代码生成；参差不齐多半有人手动改过（或是 Google Slides 转过来的） |
| 图标：线性 / 填充、风格是否统一、和文字语义是否对得上 | 按语义自动从图标库挑的（偶尔会出现配错的图标）；单色字体图标多半是插入的图片 |
| 颜色是不是模版的 accent 色 | 用的是 scheme color 还是自定义 RGB |
| 文案口吻：状态胶囊、"Verified … on …"、带版本号的限制说明 | 典型的 agent 写法，常见于跑完 PoC 后自动生成的总结页 |

## 输出结构（中文，少用列表）
1. **结论 + 把握程度**：先说是用什么做的，再说把握多大。截图上看不出具体用了哪个 skill 时直接说看不出，不要编。
2. **证据**：每条判断配上它对应的视觉证据。
3. **设计语法**：可以照抄的规则（分区、颜色含义、编号联动、结论放在哪），加上可以改进的地方（错位、空格子、图标配错）。
4. **需要准备的素材**：事实层面（组件、连线、要点、证据、限制），加上输出要求（比例、格式、模版）。
5. **复刻路线**：落到具体做法：本 skill 的模式 B / C，或者 `screenshot-to-template-slide`、`image-to-editable-ppt`。结尾给出一个可以直接执行的下一步提议。
